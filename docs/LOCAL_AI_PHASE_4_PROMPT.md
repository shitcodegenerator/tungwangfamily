# 給本地 AI 的 Phase 4 執行提示

你正在 `tungwangfamily` Godot 4 專案執行 Phase 4。請以目前 `master` 的 Phase 3 穩定版為基準，先建立新分支，例如：

```text
codex/phase-4-cc-fried-food-battle
```

先閱讀：

1. `README.md`
2. `AGENTS.md`（若存在）
3. `docs/PHASE_3_REPORT.md`
4. `docs/PHASE_3_PLAN.md`
5. `docs/PHASE_3_DECISIONS.md`
6. `docs/PHASE_4_PLAN.md`
7. `docs/PHASE_4_ASSET_README.md`
8. `assets/reference/incoming/` 下的 Phase 4 素材

## 不可自行新增的內容

- 不要替炸物魔王增加家庭原型、真實人物背景或沉重設定。
- 不要自行新增正式章節劇情、回憶、Boss 對白或家庭事件。
- 炸物魔王只有純幻想、白癡搞笑的功能性表現。
- CC 的正式台詞只使用短句，句尾加「です」；不要替其他角色套用這個語氣。
- 不要加入小怪、裝備、經驗值、技能樹、複雜屬性或完整 RPG 戰鬥框架。

## 已定案遊戲流程

1. CC 固定放在阿嬤早餐攤旁。
2. 原本的三種食物收集任務完全取消。
3. 玩家必須取得並交付一份香椿乾拌麵。
4. 交付後，CC 留在早餐攤旁，直接傳送四位角色至一次性的炸物魔王洞窟。
5. 洞窟中放置青菜、綠茶、水。
6. 玩家只能用目前操控角色按 E 撿取物品，再按 E 投擲。
7. 三種物品初版造成完全相同的傷害。
8. 炸物魔王是戴王冠的炸全雞，受到 5 次有效命中後倒下。
9. 每次命中掉一隻炸雞翅；炸雞翅落地後消失，只是命中回饋。
10. Boss 攻擊低傷害且有清楚預兆。
11. 角色受傷先以 `modulate` 變色、短暫閃爍和無敵時間呈現，不要等待受傷 Sprite。
12. 戰鬥失敗回到 CC 旁，再次傳送重新開始。
13. 戰鬥勝利回到 CC 旁，再進入 CC 接受／拒絕加入橋段。
14. 拒絕時顯示 `💢`，並顯示 OS：「你怎麼忍心!!!」，最後 CC 仍然加入。
15. CC 加入後是非戰鬥型寵物，跟在四人隊伍最後，偶爾做小動作。
16. 弟弟被切換成目前操控角色時，移動速度固定較快。
17. 回到共享家庭屋休息時才進入下一個遊戲日；不要用 F5 日夜 debug 切換觸發每日系統。

## 請分四個可驗收小階段完成

### 4A：任務、交付與傳送

- 新增 CC 的位置和互動資料。
- 新增香椿乾拌麵的取得／交付判定。
- 新增洞窟場景登錄和 CC 傳送。
- 保存返回位置為 CC 早餐攤旁，不要把 CC 傳進洞窟。
- 戰鬥失敗和完成都能返回 CC。
- 先使用 placeholder Boss 和 placeholder 物品驗證流程，再接正式素材。

### 4B：撿取、舉物與投擲

- 建立最小 `CarryableItem` 或等價節點。
- 使用既有 `Area2D`／互動流程，不建立第二套互動輸入。
- 只有目前操控角色可撿取。
- 使用 `CarryAnchor` 顯示手上或頭上的物品。
- 投擲物獨立於角色 Sprite。
- 物品沿面向方向飛行，命中 Boss 後發送 signal。
- 四位角色都能使用相同流程。

### 4C：炸物魔王

- 建立最小 `BattleDirector` 或等價控制器，只服務這一場戰鬥。
- Boss 初始 HP 5。
- 受到有效命中扣 1 HP。
- 命中時播放受擊抖動，生成炸雞翅，炸雞翅短暫彈跳後消失。
- Boss 有簡單的待機、移動、攻擊預兆、攻擊、受擊和倒地狀態。
- Boss 攻擊低傷害，預兆要足夠讓玩家反應。
- 玩家受到攻擊時使用變色／閃爍，不新增受傷 Sprite。
- 玩家戰鬥失敗時返回 CC 並重置本次洞窟戰鬥。
- Boss 勝利旗標只在第五次命中並完成倒地流程後設定。

### 4D：CC 加入與寵物

- 在返回 CC 後播放加入對話。
- 保留接受與拒絕選項。
- 拒絕時加入 `💢` 和 OS「你怎麼忍心!!!」。
- 兩種選擇最後都設定 `cc_joined = true`。
- 不把 CC 加入四位可切換角色的 party order。
- 建立獨立寵物跟隨節點，基本位於隊伍最後。
- 先做一個簡單待機小動作，再做其他好感度功能。

## 技術約束

- 使用 typed GDScript、CharacterBody2D、Area2D、signals 和現有資料驅動流程。
- 保留 640×360、1280×720、Nearest、32px 網格與現有 48×64 角色格規格。
- 不要整個重建 `TownWorld`、`PartyController`、`DialogueManager` 或現有場景。
- 不要覆蓋 Editor 已調整的位置和場景。
- 不要把 Boss 戰鬥邏輯散落在主城、CC、物品和角色腳本中。
- 先檢查 `project.godot` 的輸入優先序，對話和轉場時必須鎖定移動。
- 新增狀態要能被 `GameState`／`SaveManager` 保存，並考慮 `schema_version`。
- 所有新增素材先從 `assets/reference/incoming/` 驗證，再決定是否建立正式資源。

## 必須測試

- Phase 3 原有自動測試全部通過。
- 香椿乾拌麵未取得時不能傳送。
- 香椿乾拌麵交付後可傳送。
- 洞窟中三種物品都能撿起、舉起和投擲。
- 四位角色都能完成投擲。
- 命中 5 次才勝利，命中 4 次不能提前結束。
- 每次命中只生成一隻炸雞翅，且炸雞翅消失、不進背包。
- 受傷會變色，但不需要受傷 Sprite。
- 戰鬥失敗能回到 CC 並重新開始。
- 勝利後返回 CC，重進不會重新開啟已完成洞窟。
- 接受和拒絕都能讓 CC 加入；拒絕必須顯示 `💢` 和指定 OS。
- F6／F7 存讀檔後，任務、旗標、CC 加入狀態和弟弟速度仍然正確。
- 產出 `docs/PHASE_4_REPORT.md`，列出實際完成、測試結果、暫時 placeholder 和未完成項目。
