# 給本地 AI 的 Phase 1 執行提示詞

你現在要建立一個全新的 Godot 4 2D 遊戲專案，暫名為「山海樹港 RPG」。請依照以下規格實作，不要自行擴張到戰鬥、任務、背包、寵物或房屋內部。

## 任務目標

完成一個可執行的 Phase 1 原型：

- 建立 Godot 4 專案。
- 使用 GDScript 與 typed annotations。
- Compatibility renderer。
- 邏輯解析度 640×360。
- 32×32 地圖格線。
- 2D 偽等角／Y-sort 呈現。
- 建立一張約 960×1152 px 的巨大樹洞城主城。
- 主城至少有下層、中層、上層三段可上下探索區域。
- 四位兄弟姐妹同時出現在主城。
- 可用 1、2、3、4 或 Tab 切換主要操控角色。
- 未被操控的三位角色跟隨。
- 四方向站立與行走。
- 站立時 VisualRoot 有 1 px 的微小晃動。
- 暫時不能進入房屋。

## 角色設定

先使用簡化版原創像素角色，不要直接複製任何既有遊戲角色或商標：

專案中已附上第一版素材，請優先讀取：

```text
assets/characters/playable/phase1_playable_sprite_reference.png
assets/world/phase1_tide_root_town_reference.png
assets/tilesets/phase1_tide_root_tileset_reference.png
```

這些檔案是原型參考素材。若不能直接切成正確的動畫格，請建立同尺寸的乾淨 placeholder 或依照圖片重整，不要因為素材比例不完美而修改遊戲的 48×64 角色格與 32×32 地圖格規格。

1. 哥哥：紅鬃山犬，領袖型，紅圍巾，體格稍寬，爆氣時未來可擴充。
2. 冷靜哥：灰藍色貓頭鷹，圓眼鏡，小書袋，學者型。
3. 妹妹：胖胖的自然捲綿羊，食物袋，坦克／補師型。
4. 弟弟：溪水猴或水怪，藍色圍巾，長手長腳，活潑搗蛋。

每位角色使用 48×64 px 單格、4 方向、每方向 4 幀的 Sprite Sheet。若像素素材尚未完成，先建立同尺寸且透明背景的簡潔 placeholder，不得用任意大小圖片破壞動畫介面。

## 地圖設定

中央城鎮是巨大古樹內部形成的「潮根城」：

- 下層：樹根廣場、出生點、中央集合區。
- 中層：樹洞街、樹心、公告欄、房屋外觀。
- 上層：樹枝平台、雲霧、未開放雲端樹冠入口。
- 左側：橋頭，標示未來通往平原與森林。
- 右側：船港，標示未來通往海底根系洞窟。
- 房屋只做外觀與碰撞，不建立室內場景。

請使用一張連續世界地圖與 Camera2D，不要把三段做成三個需要切換的獨立場景。地圖的實際邊界要限制鏡頭，鏡頭不可看到世界外的空白。

## 地圖必須是真正可行走的 TileMap

請不要只把 `phase1_tide_root_town_reference.png` 當成一張背景圖片放入場景。這張圖只用來參考構圖、色彩與主城空間感；實際遊戲地圖必須使用 Tileset 重新拼接。

請完成以下內容：

1. 使用 `TileMapLayer` 建立可行走底層，地圖必須由 32×32 px 格子拼成。
2. 使用 `assets/tilesets/phase1_tide_root_tileset_reference.png` 作為主城地形設計參考。
3. 建立一條可走通的主要路線：下層出生廣場 → 中層樹洞街 → 上層樹枝平台。
4. 主要路線不得有斷路、縫隙或角色卡死點。
5. 樹皮牆、房屋牆、深水、懸空區域與地圖外圍必須設置碰撞。
6. 木橋、樹根階梯與樹枝平台必須可以正常走過。
7. 地面、裝飾與碰撞分開處理，不要用整張背景圖片推測碰撞。
8. 出生點、三段區域連接點與三個未來出口都要建立 Marker2D 或清楚的座標標記。
9. 左側橋頭、右側船港與上方樹冠入口先設定為不可離開主城的封鎖出口，但周圍必須可以走到。
10. 請以截圖或 debug 路線證明整條路線可以走通；完成驗收後可以移除 debug 標記。

請先建立「可走的灰盒地圖」，再放入樹洞、燈籠、房屋、藤蔓與其他裝飾。若 Tileset 參考圖無法直接切成精準的 32×32 格，請製作尺寸正確的簡化版本，不要把整張參考圖當成可遊玩的地圖。

## 建議資料夾

請建立：

```text
assets/characters/playable
assets/tilesets
assets/maps
assets/props
scenes/characters
scenes/world
scenes/ui
scripts/characters
scripts/world
scripts/camera
scripts/ui
docs
```

請將主要責任拆開：

- `player_character.gd`：單一角色的輸入、移動、方向與動畫。
- `party_controller.gd`：角色切換、隊伍順序、軌跡記錄。
- `follower_character.gd`：跟隨前一位角色的歷史位置。
- `camera_rig.gd`：Camera2D 跟隨與世界邊界。
- `town_world.gd`：主城初始化與出口標記。
- `debug_hud.gd`：顯示目前操控角色、座標與 Phase 1 測試提示。

不要為每個角色複製不同的移動腳本。角色差異用資料或 exported variables 處理。

## 操作

```text
WASD／方向鍵：移動
1：哥哥
2：冷靜哥
3：妹妹
4：弟弟
Tab：循環切換
Esc：離開或顯示測試資訊
```

## 動畫要求

角色場景至少包含：

```text
CharacterBody2D
├── VisualRoot
│   └── AnimatedSprite2D
├── CollisionShape2D
└── InteractionOrigin
```

站立微晃動只修改 `VisualRoot.position.y`，不要移動 CharacterBody2D，也不要讓碰撞盒上下漂移。四位角色的微晃動週期要有些微相位差。

請確保：

- 上下左右方向切換正確。
- 停止移動後保留最後方向。
- 角色行走時腳底不漂移。
- 動畫不使用 bilinear filtering。
- Sprite 使用 Nearest Neighbor。

## 跟隨要求

採用位置軌跡，不要一開始導入複雜 NavigationAgent2D：

1. 主要角色定期記錄位置與方向。
2. 後一位角色追蹤前一位角色較早的軌跡位置。
3. 距離太近時停止或減速。
4. 距離太遠時加速追趕，但設定最大速度。
5. 跟隨者遇到碰撞時不能穿牆。
6. 切換主要角色後，重新計算隊伍順序，不要傳送整隊。

## 驗證方式

完成後請依序執行：

1. 檢查所有 `.gd` 是否沒有 parser error。
2. 使用 Godot headless import 驗證專案可載入。
3. 啟動遊戲並確認主城場景能正常出現。
4. 測試從下層走到上層，再走回出生點。
5. 連續切換角色至少 20 次。
6. 測試牆角、橋、房屋外牆與地圖邊界。
7. 確認四位角色都有 idle 微晃動與 walk 動畫。
8. 擷取初始區、中段與上層三張截圖。

完成後請回報：

- 實際建立的檔案清單。
- 執行指令與測試結果。
- 尚未完成的項目。
- 目前是否能從主城下層走到上層。
- 四位角色切換與跟隨是否通過。
- 若使用 placeholder，列出未來需要替換的素材檔案。

地圖通行驗證必須另外回報：

- 從出生點走到中層樹洞街是否成功。
- 從中層走到上層樹枝平台是否成功。
- 從上層走回出生點是否成功。
- 左側橋頭、右側船港與上方入口是否能走到但不會離開主城。
- 房屋牆、樹皮牆、深水與地圖外圍是否確實阻擋角色。

## 明確禁止

- 不要加入戰鬥。
- 不要加入經驗值、等級、裝備或技能。
- 不要加入任務與劇情對話。
- 不要加入背包與寵物。
- 不要建立房屋內部。
- 不要使用第三方 Godot addon。
- 不要把地圖拆成三個需要轉場的場景。
- 不要用任意比例拉伸圖片。
- 不要為了讓程式看起來漂亮而建立難以除錯的泛用框架。

請先檢查環境，再建立檔案。每完成一個可驗證單元就執行測試；若遇到問題，先修正根因，不要用註解隱藏錯誤。
