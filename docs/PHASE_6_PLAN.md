# Phase 6：船長房間的第一個異常事件

基準版本：master commit 0a0c0b2（Phase 5：每日循環與下層樹根廣場垂直切片）

## 一、階段目標

Phase 6 不擴張世界地圖，也不新增未經作者確認的 NPC、Boss 或家庭傷痛內容。
本階段只完成一個可重複擴充的「世界事件」能力，並用船長房間的物品自行移動作為第一個實例。

玩家應該能完成：

    進入船長房間
    → 調查房間中的物件
    → 物件自行移動
    → 四位兄弟姐妹有很短的反應
    → 任務日誌新增神秘線索
    → 玩家繼續自由探索

事件的情緒不是驚嚇，而是「剛才是不是動了一下？」的安靜疑惑。

## 二、已確定的內容

| 項目 | 決定 |
|---|---|
| 事件地點 | 船長房間 |
| 事件內容 | 房間裡的物品自行移動 |
| 每日掉落物 | 換日後重置；永久旗標、CC 加入狀態與主線線索不重置 |
| 角色素材 | 完全沿用 Phase 4.6 正式行走／待機表、陰影、頭像 |
| 地圖素材 | 優先沿用現有船長房間素材，不重新生成整張背景 |
| 特效 | 舷窗水光可用 CanvasItem Shader；物件位移用 AnimationPlayer 或 Tween |
| 新 NPC | 本階段不新增 |
| 爸爸／船長真相 | 本階段不揭露 |

## 三、暫定事件表現

為了避免新增素材導致角色與畫風不一致，第一版不新增羅盤或紙張圖片。
預設使用船長房間既有的 cap_rope_coil 作為小型事件目標；它只是技術上的預設
物件，不代表正式劇情已決定物件名稱。未來若作者指定羅盤、紙張或其他物品，
只需要替換 event_target，不應重寫事件系統。

建議流程：

1. 玩家靠近航海圖桌，按 E 調查。
2. 原本的物件描述對話結束後，輸入鎖定。
3. 物件輕微晃動 0.18 秒。
4. 物件向旁邊滑動 16～24px，持續約 0.8～1.2 秒。
5. 物件輕微旋轉或回正，不要彈飛。
6. 舷窗水光短暫變亮，維持 0.8 秒後恢復。
7. 四位角色各自一行短反應；第一版標記 TEMP_DEMO_CONTENT。
8. 寫入永久旗標與線索日誌。
9. 解鎖輸入，玩家可以繼續探索。

若事件在中途被切場景或關閉遊戲：

- 尚未完成時不寫入完成旗標，下次可以安全重播。
- 已完成時不再播放完整動畫，只顯示一般的已觀察對話。
- 不得把正在移動的物件、輸入鎖或戰鬥暫態寫入存檔。

## 四、程式架構

### 4.1 WorldEventRunner

新增一個不依賴角色和戰鬥的事件執行器，例如：

    scripts/events/world_event_runner.gd

它只接受事件資料並發出完成或取消訊號。第一版至少支援：

| 動作 | 用途 |
|---|---|
| lock_input | 鎖定玩家、互動與切場景輸入 |
| wait | 等待固定秒數 |
| tween_node | 移動、旋轉、縮放場景節點 |
| dialogue | 呼叫既有 DialogueManager |
| shader_param | 暫時修改 Shader uniform |
| clue | 寫入任務或線索 |
| set_flag | 設定永久旗標 |
| unlock_input | 還原輸入 |

事件執行器不得知道「哥哥」或「CC」的特殊邏輯，也不得直接修改 day。

### 4.2 事件資料

事件資料放在 assets/reference/incoming/PHASE6_EVENT_SPEC.json 作為實作規格。
正式接線時可放到 assets/events/，但只有在載入器完成後才加入 runtime。

事件需要包含：

- event_id
- scene_id
- trigger
- once
- requires
- target_node 或 target_id
- actions
- complete_flag
- clue_id

事件旗標建議：

    captain_room_moving_item_seen

這是永久旗標，不放在 daily_state。

### 4.3 與既有互動系統接線

Phase 5 已有 captain_chart_table 的互動點。請沿用：

    Interactable → DialogueManager → on_complete → WorldEventRunner

不要在 TownProp 或角色腳本中硬編完整劇情。

## 五、Shader 使用範圍

新增的 captain_room_waterlight.gdshader 只作為舷窗或舷窗附近的環境水光。

Shader 可以：

- 讓藍色水光做極小幅度 UV 位移。
- 用 TIME 做非常慢的亮度起伏。
- 提供 strength、speed、tint 等 uniform。

Shader 不可以：

- 移動角色的地面錨點。
- 移動角色的陰影。
- 修改碰撞。
- 取代物品的主要位移動畫。
- 依賴高階硬體才看得到。

若 Shader 失效，船長房間仍應可正常遊玩；水光只是額外氣氛。

## 六、人物一致性鎖定

本階段禁止重新生成四位主角、CC、阿嬤或船長的新造型。

所有反應只使用：

- 現有正式 sprite sheet。
- 現有 idle sheet。
- 現有 portrait。
- 既有 character_shadow.png 或 pet_shadow.png。
- 對話框與簡單位移。

任何新角色圖都必須先停下來取得作者確認，不能由本階段自行替換。

## 七、地圖完整產出規格

本階段只改船長房間的事件與環境效果，不重畫整張房間。
若需要調整場景美術，仍必須維持以下結構：

    Ground TileMap
    → Wall／ceiling TileMap
    → Props layer
    → Collision layer
    → Interactable Area2D
    → Event layer
    → Foreground／Y-sort layer

每次加入建築或大型物件都要：

1. 先確定底部中央接地點。
2. 圖片與碰撞分開。
3. 不遮住出生點、出口和主要通道。
4. 以 32px 網格定位。
5. 用 snapshot 檢查 1 倍與 2 倍畫面。
6. 跑地圖驗證、單元測試和 route test。

不接受把新的完整場景背景 PNG 直接覆蓋整張地圖。

## 八、Phase 6 工作切分

### 6.0 基準與回歸

- 確認 master commit。
- 建立獨立分支。
- 先跑 Phase 5 的三道驗證。
- 保留所有舊素材與舊存檔相容性。

### 6.1 通用事件執行器

- 建立資料驅動事件格式。
- 接上輸入鎖。
- 支援中斷、完成和重播。
- 不把暫態寫入 GameState。

### 6.2 船長房間事件

- 航海圖桌互動完成後觸發。
- 預設移動 cap_rope_coil。
- 設定永久完成旗標。
- 加入一條線索。
- 事件完成後可以正常離開房間。

### 6.3 環境效果

- 套用舷窗水光 Shader。
- 保持 Nearest Filter。
- 控制效果強度，不讓畫面變成發光濾鏡。
- 事件結束後還原 uniform。

### 6.4 驗收與文件

- 新增事件單元測試。
- 新增 route test。
- 新增事件截圖。
- 更新手動測試流程。
- 報告已知限制與作者待確認項目。

## 九、驗收條件

| 編號 | 驗收內容 |
|---|---|
| 1 | 航海圖桌可以互動 |
| 2 | 事件只在第一次完整完成時設定永久旗標 |
| 3 | 物件真的發生位移，不是只改顏色 |
| 4 | 位移期間角色輸入被鎖定 |
| 5 | 事件結束後角色、隊伍、陰影均正常 |
| 6 | 離開再回來不會重播完整事件 |
| 7 | 換日不會清除神秘事件旗標 |
| 8 | 掉落物換日後仍正常重置 |
| 9 | Shader 失效時遊戲仍可遊玩 |
| 10 | validate_map、unit test、route test 全部通過 |

## 十、不在本階段範圍

- 爸爸離世事件。
- 雲端樹冠開放。
- 新平原、森林或海底地圖。
- 新 NPC。
- CC 好感度與每日餵食獎勵。
- 新 Boss、裝備、技能樹。
- 四位主角重新繪製。
- 全主城一次性重畫。
